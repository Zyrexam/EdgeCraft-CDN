# How a real CDN works (e.g., Cloudflare)

Suppose Cloudflare has edge servers in:
Mumbai, Delhi, Singapore, London, Tokyo, New York

A user from Bangalore requests:
https://cdn.example.com/logo.png

Does the browser know which edge server to use? NO.

               Client
                  │
                  ▼
         Router / DNS / Anycast
                  │
        ┌─────────┼─────────┐
        ▼         ▼         ▼
    Mumbai     Delhi    Singapore

The Router chooses.

---------------------------------------------------------

# Why store pointers in the Router?

Suppose we do this:
  vector<EdgeServer> edges;

The router would own COPIES of all edge servers.
Instead we want the Router to just observe/reference them.

Router
   ├──► Edge1 (shared reference)
   ├──► Edge2 (shared reference)
   └──► Edge3 (shared reference)

# Router Evolution

Version 1: Always choose Edge 1 (Basic connectivity test)
     ↓
Version 2: Round Robin (Current - Simple load distribution)
     ↓
Version 3: Least Loaded Edge (Route to smallest cache size)
     ↓
Version 4: Nearest Geographic Edge (Simulate latency)
     ↓
Version 5: Consistent Hashing (Ensure same URL hits same Edge)

---------------------------------------------------------

# Solving the Circular Dependency Problem

When implementing Cache Invalidation:
Origin needs to tell Router to purge caches.
Router includes EdgeServer.
EdgeServer includes OriginServer.
OriginServer including Router creates an infinite include loop!

Solution: Forward Declaration
In OriginServer.h:
  class Router; // Tell compiler Router exists
  ...
  Router* router;

In OriginServer.cpp:
  #include "Router.h" // Full implementation here
